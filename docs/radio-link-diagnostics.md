# 控制通道与本机音频诊断

Windows：**设置 → 服务端 → 手机远程操控设置 → 链路诊断**。手机：远控页面的 **电台与本机音频链路诊断**。查看不需要操作权，也不会发出查询、PTT、APRS 或信标；指标来自已有业务和播放器回调。

## 数据来源及含义

- 控制接收字节：`Radio` 收到的原始传输字节，含串口/GAIA 帧头；命令数为解析后长度足够的控制帧，不是 RF/APRS 包数。
- 同步跳过字节：GAIA 解帧重新同步时跳过的字节，不能换算为蓝牙或射频丢包率。
- 写入最近/中位/最大毫秒：提交到控制传输至 `send` 完成，包含主机/原生写入排队；不是纯空口时延。最多保留 32 个有效样本，没有样本显示未知。
- 读取往返：只对顺序读取信道/区域的匹配响应计时，从首次提交起含排队。已重试时无法可靠判断响应属于哪次尝试，不采样延迟；仍统计匹配响应、超时、重试和放弃。
- 待写、待读取和 TNC 分片：软件当前数量，断开归零；不表示电台内部队列或已发射数量。
- 本机音频接收字节/最近时间：音频 RFCOMM 接收入口；与网页刷新时间分开。
- 积压/峰值毫秒：32 kHz 单声道 PCM 的本机缓冲估计。接收解码后提交增加帧数，原生播放排空回调更新剩余值；共享播放器可能同时播放其他来源，不能把这个指标解释为 N7500 音频质量。
- 播放丢弃：提交会超过 800 ms 时舍弃新块，避免继续积压；不影响 APRS 解码/录音业务。每 PCM 块最多一秒。播放提交失败时计数并修正同一排空观察下的保留帧；若已有更新的原生观察则保留它，避免错误减去真实剩余音频。
- 最近故障：固定原因代码对应控制写入/读超时、音频连接/接收/播放故障。连接和播放可能已恢复；该项仍表示本次连接最近记录的原因。

每秒汇总发布一次，不在每个音频块或字节到达时刷新 Flutter 界面。停止/断开取消汇总计时器并立即发布最终值；重连重新计数，旧异步写入/播放失败不会污染新会话。没有观察数据显示未知，不假造零延迟或健康结论。手机标准模式每 2 秒、低带宽每 8 秒获取快照；此频率不改变主机采样。

**复制脱敏诊断 JSON** 只复制计数、固定状态/故障代码及时间，不包含 MAC/IP、异常原文、密码、定位、消息或音频。值经允许列表与类型验证；诊断不写到用户设置。

## 如何排查卡顿

1. 在卡顿前打开主机诊断，观察写入延迟、待写/读取队列和超时是否同时增长。它能显示控制路径拥堵，不能仅凭一次超时认定蓝牙环境问题。
2. 音频明显延迟时检查本机积压、峰值及丢弃；同时检查手机自己的音频图形下方缓冲恢复计数。二者对应不同播放端。
3. 手机移动网络可切换低带宽并先不加载底图；它减少网页下行音频和绘图/快照开销，无法直接改善 Windows 与电台的蓝牙信号。
4. 如果整个 Windows 窗口“未响应”，保存当时诊断 JSON 并采集进程挂起堆栈。当前指标与保护修复还不能证明实机挂起的根因。

## 验证（2026-10-03）

- 生产 `Radio` 的模拟传输验证：真实字节入口、GAIA 同步跳过、匹配区域读取 120 ms、写入失败、读取超时、每秒汇总，以及断开停止计时器，无真实 RF 命令。
- 生产 `RadioAudio` 使用模拟原生事件/播放设备/解码引擎，验证接收字节、实际播放提交、500 ms 保留帧、超限丢弃、原生排空、播放异常修正、停止和零音频发送。播放与引擎的可注入适配器用于离线验证；正常运行使用原来的平台播放器和 DSP 隔离线程。
- 有界 32 样本、时钟倒退、重试样本排除、迟到失败、排空竞争、非法排空值、隐私字段、390px 主机实时/复制/未知测试。
- 真实 390px 浏览器经生产 HTTP 登录/WebSocket 验证有值/未知面板、150 ms 写入/300 ms 读取样本、500 ms 积压与丢弃、无横向溢出、无控制台错误、PTT 禁用。浏览器用固定模拟观察；实际数据源接入由上述生产类测试验证。

没有连接真实 N7500、真实 RF/PTT/信标测试或挂起堆栈。长期蓝牙与真实音频体验仍需要实机验收。
