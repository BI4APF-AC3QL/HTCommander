# 远程慢连接：发送积压保护

手机网络变慢或停止读取时，每个 WebSocket 使用独立的有限发送队列，避免持续收听造成主机输出积压。正常连接沿用原有消息格式，不需要重新配置域名或端口。

## 行为和上限

- 每连接最多 512 KiB 消息载荷、128 条消息；正在写出的消息也计入预算。写入串行推进，并在消息之间让出事件循环。
- 容量不足时先丢弃尚未发送的旧音频，保留控制消息的顺序。未发送音频超过 500 ms 后丢弃，恢复网络后不会回放这些旧块。
- 单次写入超过 3 秒、写入失败、控制消息无法放入队列或单条控制消息超过 512 KiB，会关闭该连接，触发既有断线清理和操作权释放。已经交给操作系统的数据无法撤回。
- 撤销登录和关闭服务直接销毁底层连接，不等待慢客户端完成发送。撤销同一登录会话时，该会话的其他连接也会关闭；独立登录不受影响。
- 使用公开的 dart:io WebSocket 解析器，保留 Cookie/Origin 校验与八客户端上限，不协商消息压缩。输入单条消息（含分片累计）上限为 64 KiB。

512 KiB 上限也适用于旧完整网页的设置、邮件等大快照。超过上限会明确断开，不截断内容；遇到此情况需缩小快照或后续实现分批协议，不要通过无限增大队列处理。

## 如何查看和排查

手机的音频统计显示“主机待发”和“主机丢弃旧/积压音频块”。它们按连接统计，表示软件队列中的消息载荷及丢弃次数，不包含操作系统/TCP 缓冲，也不能证明手机已收到、播放或电台 RF 丢包。

如果待发量持续增加或掉线，先选择低带宽收听，并检查手机网络、电脑休眠和蓝牙环境。恢复网络后重新连接、申请操作权。固定日志原因 `output_write_timeout`、`output_write_failed`、`output_queue_overflow`、`output_message_too_large` 可区分输出保护触发方式。服务器没有把“加入队列成功”当作实际交付。

## 测试范围

新增九项队列回归测试：十万块音频、独立健康连接、容量含正在写出的帧、控制顺序、可变缓冲复制、UTF-8 字节、音频过期、超时、同步/异步错误和撤销后的迟到完成。

新增五项生产回环测试：并发升级保持八连接上限；原始 TCP 客户端完成升级后关闭读取事件，持续输入合成 PCM，验证容量/丢弃和三秒超时；同样的积压条件下撤销和关闭服务及时完成；正常 WebSocket 接受 64 KiB，拒绝超限消息且不交给控制回调。慢连接使用原始 socket 停止读取，避免把浏览器暂停播放误当网络阻塞。

生产手机页面脚本覆盖新增统计字段及缺失字段；真实浏览器门禁仍使用生产 HTTP/WebSocket、合成媒体和模拟电台。没有进行真实 RF/PTT/信标测试，没有取得实际 Windows 未响应时的挂起堆栈；此修复限制已识别的输出积压风险，不证明实机卡死根因。

本地验证（2026-10-04）：556 项 Flutter 测试、静态分析和生产页面脚本通过；390px Chromium 151 无界面浏览器验收通过，没有控制台错误。独立 PWA 窗口由 Windows 发布门禁另行验证，本地无界面结果不作为独立窗口证据。
